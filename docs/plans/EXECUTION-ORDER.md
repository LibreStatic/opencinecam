## 4. Proportional testing and coordination

- Each change receives focused tests of the affected behavior. Reuse previous valid results, with reference to source, environment and the limit of what was demonstrated.
- Broad regression when closing a block or upon justified cross-cutting impact (e.g. capture/transfer ownership), not after every documentation adjustment or isolated finding. This audit does not trigger another regression.
- Decode media again only if byte production, timing, container or file relation changes, or there is a failure in that walkthrough. A configuration/socket cleanup change does not by itself justify regenerating all the media.
- Keep failures and validate corrections; do not remove asserts, repeat until passing, reduce cases or equate in-memory HTTP with real TLS. Test counts are evidence, never a measure of functional progress.
- Comply with preservation of originals, rollback and evidence required by higher-level instructions, reusing the open checkpoint where appropriate. Do not create a new family of copies/artifacts for the same operation without technical reason.
- Root centralizes Gradle/ADB and integrations. Each subagent has an independent file/subtask; reviews during tests are read-only. No agent overwrites concurrent work. Non-blocking findings are recorded in the queue and do not automatically expand the active deliverable.
